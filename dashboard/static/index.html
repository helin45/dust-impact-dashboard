What this is

A local dashboard for exploring core dust ingestion across flight phases, built from per-flight recordings of aircraft engine and flight data. It is built to help identify and characterize the impact of airborne dust (including dust storms) on aircraft engines.

The data

Each row is one timestep from one flight, recorded roughly every 4 to 10 seconds. The key column throughout this dashboard is CoreDustIngested_g: the mass of dust ingested by the engine core during that single timestep (not a running total). Flight phase (CLIMB / CRUISE / DESCENT / LEVEL DESCENT) and altitude (Alt_ft) are the two other columns used everywhere. Rows recorded as UNKNOWN phase, and any flight whose recording doesn't reliably start in climb, are excluded automatically before they reach any chart.

"Elapsed time" on any chart is re-zeroed at each flight's first usable row, not the raw recording start, so flights are comparable regardless of how much ground/taxi time was captured before they got airborne.

The tabs

  • Aggregate view: filter across the whole dataset (aircraft type, date, takeoff time, phase, altitude, location, registration) and see distributions, trends and rankings.
  • Single flight view: inspect one flight in full detail: flight path, phase timeline, altitude, speed, dust profile.
  • Dust source attribution: a HYSPLIT backward- dispersion map of where a selected flight's dust likely originated. Can compute it on demand for a flight that doesn't have it yet.
  • Compare flights: overlay 2 to 8 individual flights on the same charts, each in its own color.
  • Compare filters: hold a snapshot of the current aggregate view (its filters and results), change the filters and hold another, then see them overlaid.
  • Routes: a geographic view of every route flown, colored by total dust ingested.

Every chart has its own ⓘ Info button explaining exactly what is plotted and how it is calculated.

Map display

Pick which soil/land-cover layers count toward "confirmed sources" and how many of them need to agree. Defaults to all 5 layers, majority agreement (the original fixed behavior).

What do these toggles do?
  • Only show confirmed sources (susceptibility gated). Hides any part of the HYSPLIT result that falls outside an independent soil and land cover model's plausible-source area, leaving only the overlap between the two independent methods. Which layers count and how many need to agree is configurable below this toggle once checked.
  • Show true-color land imagery. Adds a real satellite photo of the ground (NASA VIIRS true-color, same day as the flight) as a background layer, so you can see actual terrain -- desert, vegetation, water, urban areas -- under the modeled source region instead of just blank map axes.
  • Show terrain relief. Adds a greyscale hillshade (NASA ASTER GDEM elevation model) as a background layer instead of a photo, so rugged/rocky terrain -- mountain ranges, escarpments, wadis -- is visible directly, unobscured by cloud cover or vegetation. Independent of the true-color imagery toggle above; both can be on at once (terrain draws on top).
  • Show land surface temperature. Adds MODIS ground temperature (same day as the flight) as a background layer -- hot bare sand/rock reads yellow/orange, cooler vegetated or wet ground reads green. A rough proxy for exposed dry surface versus vegetation or moisture. Independent of the other background toggles; any combination can be on at once.
  • Show MERRA-2 wind vectors. Colors each release point by how closely an independent weather reanalysis's wind direction agrees with the direction back to HYSPLIT's own modeled source (see the colorbar), plus an arrow showing which way that wind was actually blowing.
  • Show wind-only back-trajectory. Draws a straight line from each release point showing where the air would have come from if the wind measured there had stayed constant for a set number of hours. A simplified, independent check, not a full simulation like HYSPLIT.
  • Overlay other method. Draws the OTHER method's result (surrogate if you're viewing HYSPLIT, or vice versa) as outlines on top of this map, plus how much their high-density regions overlap -- computes it first if it isn't already. Logged to the Model performance tab's comparison table.

Tracks the trained HYSPLIT surrogate model itself: how much data it's trained on, how well it cross-validates against flights it's never seen, and (below) how far its estimates land from real HYSPLIT runs on flights that have both.

Retrain

Rebuilds the model from scratch using every combined_raw.csv currently on disk (hysplit_tools/surrogate_model.py). Takes a while once there's a lot of training data -- safe to leave this tab and come back.

Surrogate vs. real HYSPLIT

For every flight with both a real HYSPLIT and a surrogate result computed (same strategy), how much the two methods' high-density source regions overlap (Jaccard, percentile-thresholded -- same method as the AOD agreement stat) -- a spot check of surrogate accuracy against real physics, independent of the training-time CV metrics above.

% of HYSPLIT area in surrogate -- of HYSPLIT's own high-density cells, how many the surrogate also flagged (a low value means the surrogate is missing real source region, a false negative).

% of surrogate area in HYSPLIT -- of the surrogate's own high-density cells, how many HYSPLIT also flagged (a low value means the surrogate is guessing too wide, a false positive).

Susceptibility agreement

For every flight with a real HYSPLIT result, what percentage of its own high-density source region is independently supported by the susceptibility grid (soil and land-cover data, entirely separate from the transport modeling) -- run offline via hysplit_tools/validate_susceptibility_agreement.py, since it needs every already-computed flight on disk rather than just the current one.
